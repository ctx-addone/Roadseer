# 纵向道路与车辆背包：布局概念

日期：2026-10-23。状态：用户已选择 A，当前已完成布局与交互首轮实现；运行细节见《UI布局与交互》。本文保留当时的设计比较与提示词。

使用 brainstorming、visual-style-direction 规划，内置 image_gen 生成三个独立方案。没有修改游戏代码。完整提示词见 [prompts.json](prompts.json)。

## 设计主张

左侧回答“前方发生什么”，中间回答“我带了什么、能做什么”，右侧回答“现在如何处理”。道路提供行进感，背包提供决策空间；只在玩家需要处理时展开详细操作。

固定关系：最上方 HUD；下方从左到右为纵向道路、竖直车厢、情境面板。路上的车位于下方并朝上行驶；背包车辆也车头朝上。点击车内制作台才显示配方。正常道路战斗继续以自动战斗为主。

| B 公路旅途 | 环境优先；道路形成连续景深；右侧采用紧凑面板 | 45/33/22 | 遭遇、服务区、高温天气变化更有代入感 | 长车和多层设施易拥挤；远近景、天气、道路事件美术成本较高 |

## 推荐布局和状态变化

建议从 A 开始选择。保留道路与车厢同时可见，右栏设备插画缩至面板高度约 15%，主要面积交给材料缺口、消耗和按钮。LOGO 也应缩小，把 HUD 让给日期、灾难目标和生存资源。

| 状态 | 左侧道路 | 中间车厢 | 最右侧情境 |
| --- | --- | --- | --- |
| 行进 | 地面向下滚动，车保持下方；突出最近一个遭遇，远处最多一个提示 | 常驻，显示已装物资 | 今日目标、下个遭遇摘要 |
| 物资箱/破损车辆 | 接近后停住并高亮交互对象 | 保持可见；搜集完成后下方展开待装物资条 | 搜索收益、行动消耗、搜索/略过 |
| 服务区匝道 | 接近分岔时暂停，明确两条去向 | 保持可见 | 驶入/继续前进及其代价；服务区具体功能后续设计 |
| 敌车/僵尸/怪物 | 当前敌人靠近并进入自动战斗；受击、弹道、血量反馈集中在道路 | 保持可见但暂锁整理，标出触发的武器/防护 | 暂停、倍速、战斗摘要 |
| 机缘 | 特殊地标与明确问号标签，接近后暂停 | 保持可见 | 事件描述与选项；内容不在本轮确定 |
| 查看/整理设施 | 进入规划暂停，道路不推进遭遇与消耗 | 选择、拖动、旋转 | 选中设施操作；制作台→配方→详情 |
| 日结 | 停车，降低场景亮度 | 仍然可见 | 消耗结果、灾难准备缺口 |

道路滚动是现有行动流程的表现方式。它不自动引入持续计时、持续耗油或手动驾驶规则。是否改变出行节奏需另行验证；菜单、选项、整理期间不催促玩家。

## 视觉规则与交接

- 保持：竖车、四列逻辑网格、同一车辆两种尺度、同一状态一致的资源数字。初始 4×6，扩容 4×8/4×10。网格区域随车长延展；先验证适配，再决定缩放/滚动。楼层切换保留设计空间，不提前展示已解锁车顶。
- 可变：三栏比例、明暗面板、环境景深、物品插画细节。道路背景装饰不能与可交互对象采用相同高亮。
- 避免：把所有遭遇一起摆满道路、常驻完整制作菜单、设备大图挤走按钮、游戏进行时自动滚走背包、只用颜色表达警告。
- 字体：落地沿用项目中文字体方案，缺字用系统中文无衬线字体回退。原型目标正文 16–18 px、次要文字不低于 14 px（1440×900 起点，待实机验证）；概念图文字不作为实际 UI 素材。
- 画面：道路和物品受左上方柔光，UI 本身不承受环境阴影；磨损仅放在车壳、道路和物品，不铺到正文背景。背包使用正交俯视，避免景深影响格子判断。
- 动效：道路向下移动表示前进；发生遭遇减速停住；选中物品描边与右栏同步。低动态模式用静态道路和事件位置变化替代连续滚动；不用闪烁提示。
- 可读性：关键文字置于实色面板，交互状态兼具文字、图标与描边。实现后验证文字对比、色弱辨识、1280×820 和 1440×900。当前仅概念图目视评审，未完成真实游戏交互/无障碍验收。
- 色彩交付：普通 SDR 预览；未作显示器校准或色彩档案认证。实现采用独立 UI 色值，避免从生成图反向采样作为唯一规范。

## 图片评审与边界

已检查三图：都有顶部 HUD、左侧道路及下方玩家车、中间竖车、右侧制作台；A 均衡、B 道路更大、C 浅色设施界面，能够比较方向。

生成偏差：C 没有严格达到 26/46/28 的目标比例；多张图把一件 1×2 物资画成两只容器，部分格线和数量标记不够明确；道路小车出现了太阳能板等装饰，不能理解成开局已解锁设备。实际实现必须按状态模型精确绘制占格与设备。右栏插画和 LOGO 偏大，落地时缩减。

素材来源：三图由内置 image_gen 依据原创提示词生成，没有输入第三方游戏截图，也没有要求仿制特定游戏。用途为布局与氛围比较，不是已批准的正式美术资产；生产使用前仍需检查像素、字形、网格、设备一致性。

## 选择后的验证

1. 用选定方向做一个真实界面，先验证打开制作台、拖动 1×2 物资、拿取物资箱、遭遇自动战斗。
2. 验证初始与扩容车辆，战利品条展开后核心按钮仍可见。
3. 验证高温期 HUD 的灾难目标与资源缺口，避免道路画面抢走生存预警。
4. 用户实际游玩后再确定美术细度和出行节奏。当前没有合并三个方向，也没有默认批准某个方案。

## 决策记录

用户指出生成图 A/C 除画风外没有明显结构差异；接受该判断，C归为同布局的浅色皮肤，不再视为已验证的独立玩法布局。随后用户明确“A合理，按照A推进”。本轮实施A的三栏关系与道路/车厢同屏，原型美术不等同于生成图最终资产。
