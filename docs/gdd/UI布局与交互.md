# 车辆中心 UI 与设备交互

日期：2026-10-30。状态：保留 A 布局，行进已改为车速与里程驱动。依据：顶部HUD、左侧纵向道路、中间竖直背包、最右侧情境面板；制作台等二级功能由点击物品展开。

## 本轮行进交互（覆盖下文旧选路规则）

HUD显示剩余游戏时间，替代行动次数。左侧显示真实车速、累计/当日里程与宝箱计数；开始行驶后沿路自动入舱，容量不足自动停车，保留溢出物资。大型地点抵达时暂停，直接在左侧选择耗1小时探索或免费略过。车速40/60/80由制作台升级；“播放×1/×2”只改变等待时间。行驶期间可主动靠边停车整理，右侧展示下个事件距离、奖励和风险。详见[当前设计](../superpowers/specs/2026-10-30-distance-travel-design.md)。

下文保留此前布局设计记录，其中四路牌选路、每日一次探索、2行动及固定3秒行进已被本轮替换。

## 布局

- 顶部：日期、灾难倒计时／阶段、剩余时间。下一行显示主角健康、车体、水、粮、油、弹；“成员1人”入口查看座位和床位。
- 左侧：常驻纵向道路，车辆位于下方、车头朝上。场景展示前方物资箱、破损车辆、电站、武装物资车；行进/战斗时地面滚动，停靠时停止。
- 中间：竖直俯视车辆，车头朝上。4×6逻辑网格直接对应4列×6行。扩容后车厢独立滚动，格子最小约48像素；鼠标拖动接近上下边缘可滚动。三栏参考约37/40/23，按窗口和侧栏内容最小宽度适配。
- 车厢下方：有待装物资时展开横向物资条；空时收起。图标、数量、占格与悬停说明帮助判断。
- 右侧：单个情境面板。首页安排、设备使用、配方、路线、预报、日结、记录按当前操作切换。
- 底部：今晚水粮／制冷油需求、热伤与短缺提示，以及结束当天按钮。

不常驻逐条日志、无战斗的战场、全部配方和长期操作说明。信息用明确入口按需展开。

## 点击设施，再展开操作

| 对象 | 点击结果 |
|---|---|
| 已装车的制作台 | 配方列表、扩容入口、移动／卸下 |
| 制冷机 | 设备说明、夜间制冷开关、移动／卸下 |
| 修理包 | 数量、使用条件、使用操作 |
| 武器、装甲、物资与座位 | 效果／数量说明、适用的整理操作 |
| 待装物资 | 进入放置状态，可旋转、放入或合并 |

车内点击首先检查或使用设备。点“移动”、按R或直接拖动进入整理，避免查看制作台时误搬位置。点击另一件车内物品会改为查看它。

没有制作台时，首页提供“搭建制作台”，仍按原配方消耗2金属和1行动，成品进入待装区。制作台尚在地面时优先提示安装；装车后通过点击进入配方。不会因为二级入口依赖设施而堵住开局或丢失设施后的恢复路径。

## 整理与制作

- 拖动支持车内移动和地面物资装车；同类物资可合并。拖动保留抓取位置偏移，R旋转后重新从首格定位。
- 点击放置沿用物品左上角定位。红色表示冲突，失败保留原物；Esc／右键取消整理。
- 点击配方查看成品占格、作用、所需材料、缺口和来源。可追踪一张配方，首页显示当前缺口。
- 制作成功后选中新成品，提示放入车厢；材料消耗和地面规则保持原有实现。
- 外出或结束当天仍需确认放弃未装车物资。

## 探索、战斗与日结

左侧道路直接展示4个可点击路牌：物资箱、破损车辆、电站遗址、武装物资车，标明资源与风险。点击路牌免费选中，右侧只展示这一条路线的详细情报，左侧道路下方确认出发。右侧完整路线列表与“选择探索路线”总入口已移除。

出发时一次性扣除外出消耗，约3秒的道路行进后抵达。安全补给先等待玩家点击道路物资箱或开箱按钮，开箱不重复收费；敌对路线抵达后直接自动战斗。

战斗在左侧道路发生，车厢始终可见；侧栏显示自动作战说明、累计耗弹/防护/车损和已装武器／防护。保留暂停与速度控制，行进、遭遇处理与战斗期间锁定背包。触发武器和防护时车内物品短暂高亮；胜利后下方展开战利品。记录入口显示快照，并可手动刷新。

结束当天后侧栏显示当晚水粮、制冷油、健康变化和具体结算。失败或完成周期显示结果与重开入口。灾难预报先给是否能撑过、库存与需求、预计剩余健康，再解释假设和计算规则。

## A 方案实施边界

- `begin_journey → arrive → encounter/combat → stop` 表达道路阶段；同步 `explore` 仍供纯模拟使用。一天一次外出、材料和灾难数值不变。
- 左侧路牌已经接入实际路线选择，不提供服务区商店或额外奖励；僵尸、机缘等尚未扩展为新遭遇系统。
- 道路与车辆使用 Godot 绘制的2D原型图形，落实A的布局、方向和配色层级，尚未替换为概念图的细节美术。没有把概念图中的太阳能装饰当成已解锁设备。
- 菜单提供减少道路动态选项，暂停背景滚动，保留遭遇进度及战斗信息。
- A布局通过真实引擎输入事件检查开箱不重复领取、出发不重复扣费、行进暂停、战斗与车厢同屏、竖向旋转/拖放、扩容滚动、地面确认与日结。两条21天生存路线回归结果不变：隔热方案健康8、制冷方案健康38；均车体29。

## 单人成员、座位与床铺

- 默认主角1人，3个客座为空；小爱是自动作战系统，不属于占座成员。HUD健康即主角健康，人数独立显示。
- 驾驶位和客座均占1格、各容纳1人。主角通过座位ID绑定驾驶位，移动座位不会丢失人员；驾驶位未装车或主角不在驾驶位时不能出发。本轮原有座位仍保留，不新增招募与换座操作。
- 开局自带1张单人床，标准1×2，可旋转成2×1，初始横放在座椅后方。每床只供1人，当前主角自动使用第一张装车床；床不在车内则不分配。
- 夜间结算记录主角睡眠；没有缺粮、缺水和热伤且床位足够时恢复2健康，无床不恢复。预报与日结使用同一规则。当前不引入疲劳、睡眠时长和多成员健康系统。
- 床可移动或卸下。缺床时首页给出恢复床位入口，可用2金属、2布料、1行动制作单人床，无需制作台；地面成品须装车才有效。
- 新开局使用18/24格（4格座位、2格床、12格既有设备与物资），相较此前净释放2格。
- 成员规则、左侧选路、1440×900/1280×820界面及滚动拖放验证通过；两条全程保留床铺的21天路线结果仍为健康8/38、车体29。
