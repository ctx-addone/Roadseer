# Roadseer PC 车辆背包与 MVP 提案

2026-10-22讨论补充：常规公路遭遇以自动战斗为主；副本版本的战斗交互另行讨论。玩法组合、参考游戏及新一轮验证优先级见[玩法方向与参考游戏](玩法方向与参考游戏.md)。下文旧的实时战斗候选不表示已经采用。

## 1. 已确认的共同核心

- 首发验证目标是 PC，使用 Godot；完成 MVP 后再评估手机移植。
- 核心玩法是车辆网格背包：在有限格子里容纳驾驶、乘员、生产、生活、存储和战斗设施。
- 初始横向4格、纵向6格。驾驶位占1×2，3个客座暂都占1×2；用户已同意先用这个占位验证。
- 当前测试布局为前两排四个座位，后两排后备箱标识区，中间两排可用空间。后备箱是车内分区，暂不嵌套第二套背包。
- 车辆升级扩展尺寸与楼层；最多两层车内加一层车顶，车顶需升级解锁。
- 车内包括驾驶位、房间、卫生间、厨房、培养皿、存储室、作战指挥室；车顶包括太阳能板、机械臂、无人机平台。
- 目标是逐步自给自足；不同车辆方向改变空间、生产、探索和作战解法。
- 长期经营、持续奖励、流派构筑可以共存，不作为互斥选项。

## 2. 网格与生产规则

### 2.1 空间是主要预算

物品记录尺寸、朝向、所在楼层和位置。碰撞、越界、楼层限制会阻止放置。换装失败保持原位置，旋转在确认放置前仅是预览。驾驶位必须保留在第一层；座位可移至待装区，但未来减少座位应影响乘员上限。

原型暂用矩形占格；后续可测试不规则轮廓、相邻加成和通道，但这些不是首轮必需。房间先作为占格功能块，不同时实现可进入房间的内部装修。楼梯占格、设施入口和乘员寻路应在“是否模拟车内人物”确定后再加入。

后备箱当前只标识存储区域，设施也可放入；不等于已经实现物资实体占格。P0 里设备占格，普通资源用数字库存。P1 必须补物资箱／资源堆叠占格，验证战利品、生产设备与生活空间的真正竞争。

### 2.2 设施分类与 MVP 职责

| 设施 | 原型占格 | 需要验证的作用 | 后续深化 |
|---|---|---|---|
| 驾驶位 | 1×2 | 行驶前置，第一层固定职能 | 驾驶员与自动驾驶 |
| 客座×3 | 各1×2 | 占位与重排空间 | 乘员容量、伙伴专长 |
| 房间 | 2×3 | 休整恢复加成 | 睡眠、舒适与乘员分配 |
| 卫生间 | 1×2 | 回收节水 | 卫生状态与污染处理 |
| 厨房 | 2×2 | 原料→食物 | 配方、燃料与料理加成 |
| 培养皿 | 2×3 | 水＋电→食物原料 | 多作物、生长周期 |
| 存储室 | 2×2 | 提高普通资源容量 | 箱内物资格子和堆叠 |
| 指挥室 | 2×2 | 降低遭遇损失 | 作战指令与伙伴调度 |
| 集水器 | 2×2 | 可见的稳定供水 | 环境产率与净化 |
| 太阳能板 | 2×2，车顶 | 电力供给 | 天气、储能、夜间供电 |
| 机械臂 | 1×3，车顶 | 提升回收收益 | 自动拾取和清障 |
| 无人机平台 | 2×2，车顶 | 情报与遭遇支持 | 侦察范围、维修、任务 |
| 雕像 | 1×1起 | 特殊产出与构筑效果 | 多种触发和互斥规则 |

除驾驶位与客座的暂定占格外，这些具体尺寸与效果是测试参数，均未作为最终平衡确定。

### 2.3 自给自足的可验证定义

停车、不拾取、不交易，连续运行若干回合后，水、食物不出现持续净损耗；同时生产链投入得到供应。建议以连续5回合观察作为第一轮检查，再测试天气或设备损坏导致的脆弱性。

测试链：太阳能板→电力；集水器→水；水＋电→培养皿原料；原料→厨房食物；卫生间回收降低用水。太阳能提供电力不代表车辆行驶无需燃油，后者属于额外的动力升级方向。

不能仅看一次库存上涨宣布自给自足：要区分消耗开局库存与真正的净供给。自给后仍需稀有材料、晋级凭证、图纸和世界适应设备保持探索动机。

### 2.4 车辆成长

原著十级框架保留作长期参考；最终各级尺寸与解锁尚未确定。三案均要求一次明显扩容、一次分支和一次楼层变化，避免只用战力数字代表成长。

P0 为加速测试采用：Lv1 4×6；Lv2 4×8；Lv3 6×8且开第二层、选探索／家园；Lv4开车顶。此处把分支提前至3级是原型压缩，不改写原著四级首次专业分支的事实。

探索型暂降低耗油，家园型暂提高供水。下一步应加入更明显的空间或安装差异，例如探索型偏车顶工具和通行、家园型偏车内生产与生活，而非只保持两条倍率。

## 3. 原著结局与游戏胜利目标

本轮已回查本项目小说原文：

- 第1569章《入侵世界核心，编写规则》：张拓海获得镇域天雷锁，介入两界融合并编写规则，取得世界控制能力。
- 第1571章《老子不玩了（完结）》：经历十年混乱后，他发现世界并未按期待走向和平，最终向世界核心输入重启指令，世界恢复太初并开始出现新生命。

因此可以说他取得了压倒性力量和规则权限，但“世界获救、和平大团圆”并没有发生。终局也不是普通的最终 Boss 战后通关。小说的开放式重启可作为主题参考，不能当作用户已决定采用的玩法结局。

建议游戏独立定义胜利：突破最后灾难、建立能够自主存续的移动家园，或取得摆脱强制求生规则的权限。Boss 是能力检验载体，是否重启世界可以是剧情结尾选择；单局重开功能不必强行解释为小说结局。

## 4. 三个候选版本

| 维度 | V1 单局完整成长 | V2 剧情战役 | V3 远征式持续经营（新增候选） |
|---|---|---|---|
| 用户目标时长 | 单局30—120分钟 | 完整体验2—10小时 | 单次远征10—25分钟为测试目标，长期总时长未定 |
| 核心追求 | 在有限时间形成自给与战斗构筑并通关 | 随章节推进，让同一辆车逐渐成长并完成故事 | 带着明确需求出征，撤回整备，再挑战更远地区 |
| 开局 | 每局1级，无局外成长 | 新战役1级，章节间持续保留 | 新存档1级，远征间持续保留 |
| 保留范围 | 局内全部保留；输赢后重开归零 | 车辆、图纸、伙伴、剧情与库存 | 车辆、图纸、设备；带回物资结算入库 |
| 暂停 | 可暂停，暂停存档仅恢复本局 | 手动／自动存档与章节检查点 | 整备存档＋远征中断恢复 |
| 失败 | 本局结束，复盘后重开 | 检查点重试，可比较不同改装 | 损失未带回战利品、承受维修成本；不清空已建家园 |
| 随机性 | 路线、掉落、模块组合 | 固定主线＋部分可选事件 | 区域资源和遭遇变化，需求驱动选区 |
| 自给的价值 | 为本局后半段腾出行动预算 | 长期改善生活与进入新环境的能力 | 降低出征补给成本，提升可抵达距离 |
| 胜利 | 终局灾难／Boss与生存检查 | 最终章节与Boss、结局 | 阶段远征目标和最终大型远征；可继续经营 |
| 原有方案如何融入 | 随机构筑结构，探索与战斗强度可调 | 生存经营＋剧情，可用实时或策略战斗 | 生存经营＋探索刷取，是否实时战斗可独立测试 |

V3 是供比较的新提案，不是已选定方向。三案都以网格构筑和常规公路自动战斗为共用核心；第一轮采用相同的遭遇，以免战斗交互差异干扰对流程结构的判断。特殊副本的交互另设验证片段，不默认采用实时车战。

## 5. 共用 P0 与三案 MVP 内容

### P0：共用车辆背包底座（本轮已有可运行版本）

范围：初始4×6、四个座位、设备待装区、点选搬移、旋转、重叠与越界限制、车内／车顶区域限制、扩容、二层和车顶解锁、两条测试分支、资源拾取、简化战损、生产消耗、一次终点结算和重开。

P0 验证“摆放与扩容能否带来真实取舍”“设备收益是否可读”“两层加车顶是否好操作”。它没有完整世界、副本、真实战斗、正式存档和剧情，不能称作30—120分钟单局或2—10小时战役。

### V1-MVP：单局成长验证

目标先做约30分钟的可通关切片，再讨论是否扩至120分钟。

- 3个连续阶段：资源紧缺、扩容分支、终局检验；每段有普通探索、一个特别事件和阶段挑战。
- 压缩到4级测试成长，覆盖首次扩容、两种分支、二层、车顶；完整1—10级路线是之后的内容需求。
- 8—12类可拾取模块、3种雕像、至少2条可自给的配置路线；关键晋级资源有保底来源。
- 物资箱占格、堆叠、拆卸搬移；拾取时空间不足必须能放弃或置换，不能静默删除战利品。
- 一次“当前物资／下一阶段预知”选择；下一阶段需求必须对前面的摆放与资源选择有影响。
- 阶段战斗和终局挑战，先用可解释的战术结算；完整失败、胜利、复盘、重新开局。
- 暂停和中断恢复，恢复本局不能刷箱；没有永久属性、局外材料或强度解锁。

验收：完整走完一次闭环；用两个分支分别通关；改变掉落和路线后产生不同摆放；玩家能解释一次取舍；无关键随机物锁死。观察每个阶段耗时，再调整到目标时长，不把空等或刷重复节点当作内容。

### V2-MVP：剧情战役验证

先做一个约30—45分钟的完整章节切片，2—10小时是完整游戏目标。

- 一条有起因、目标、转折、章节Boss和收尾的主线；一位独立车辆伙伴、一项支线或可选副本。
- 章内一次扩容和分支，章末进入第二章的短过渡；二层／车顶用后段预设存档验证，不强迫第一章耗尽全部成长。
- 与剧情相关的两种建设需求，例如收留伙伴需要座位／房间，穿越低温需要供暖／供电。
- 同样的物品占格、替换、雕像与基础生产，保留全部家园建设；剧情奖励解锁新模块。
- 一个预知片段和一个真正用到准备成果的后续场景。
- 战役存档、任务状态、物品状态与伙伴状态保存；Boss失败从检查点恢复，剧情奖励不能重复获取。

验收：玩家能说清当前故事目标；改装是推动剧情的方法之一；关闭重开后任务与布局一致；章节过渡保留资产；故事节奏给整备留出时间，不靠长段文字掩盖无玩法。

### V3-MVP：远征式持续经营验证

先验证两次有区别的完整出征—回车循环，总体约20—40分钟为测试目标。

- 一个整备界面、两个资源倾向不同的区域，以及一个阶段任务终点。
- 每次出征选择补给、空余货舱和设备；一次遇到“继续深入还是撤回”的明确取舍。
- 8类设备、3种雕像、基础生产和一次扩容；第二次出征前可以重排成不同用途的车。
- 车体与已安装设施持续保留；新拾取货物在撤回时入库。货舱容积影响收益，不只看材料数。
- 暂不设置物理安全区大地图，停车整备即可；不做永久损毁车辆，先测试修理负担是否合适。
- 一个情报工具和一个下一远征需求，验证先获知情报再配置车辆。
- 整备与远征保存、撤回／失败结算、一次最终远征；明确损失范围。

验收：第二次出征前的布局至少发生一次有理由的变化；继续探索和撤回都有合理情境；失败有代价但不摧毁已建家园；生产改善下一轮出征预算；两个区域不是同一刷取任务换名字。

## 6. 怎么安排多个 MVP

建议“一份P0底座＋三个独立流程切片”，共用网格、设施、库存、生产和晋级模型。只有流程、奖励、保存和失败规则按V1/V2/V3拆开，避免复制三套引擎工程。

顺序：先验证P0摆放，再补物资占格和基础生产账本；用相同素材完成V1单局切片；复用基础能力做V2章节切片及V3两次远征。此顺序基于共用依赖，不代表最终产品优先选择V1。

本轮不承诺三个完整模式已实现。正式开始某个切片前要确定：战斗交互、设施入口是否需要通道、乘员如何影响需求、座位是否可拆，以及物资堆叠规则。无需先决定所有十级车型，也不需要先做整段小说。

共同观察：摆放改变了什么能力、升级是否令人期待、奖励是否引发新选择、生产链是否帮助继续探索。分别观察：V1重开意愿和单局节奏，V2故事牵引和持续建设，V3出征配置与撤回判断。用这些行为决定继续哪案，不只比较完成时间。
